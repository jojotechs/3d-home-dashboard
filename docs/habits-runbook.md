# H01 习惯农场使用与维护

2026-10-21。**H01 已上线并通过生产验收**。在[家庭小城](https://3d-home-dashboard.vercel.app/)登录后，点击底部「习惯」即可打开本人农场；证据见 [H01 验收记录](verification/h01-results.md)。复用现有 Vercel、Supabase Auth/Postgres 和家庭身份；平台配置、邮件及既有财务维护继续参见[一期使用与维护](phase-one-runbook.md)，不改写其历史交付记录。

## 当前可用范围

H01 只交付本人、私密、每日手动打卡和雏菊种植；显示习惯列表与当前选中的一个真实种养位。计量、其他周期、公开分享、归档、六位分组、出售、付费商店、动物和购买设施属于后续票。本人的习惯不增加住宅、健康或财务成长，访问习惯不需要财务授权。

- 首次进入为 0 农场币、空习惯与空种养；不创建示例、不导入本机 demo。本人创建习惯，按明确数量领取免费种子，再选择对应习惯并确认播种。领取种子不会替未播种习惯自动选择品种。
- 可以先打卡、后播种。每个应做日最多一次有效完成；习惯日按北京时间 **04:00** 切换，例如次日 00:20 仍记入前一日。没有补记历史或记录未来的入口，睡眠目标由本人确认。
- 只有云端确认才算保存。每条记录自首次成功起可撤销 **30 秒**；刷新、重试和换日不延长。03:59:50 成功的记录可撤销到 04:00:20，但不能在新一天补录旧日。到期后记录锁定。
- 撤销期内只显示成长预览，不产生可收取资产；到期后每天达标发一格，三格完成一轮。未种植或缺种子时，成长留在原习惯，不转给其他习惯。
- 每轮消耗一包种子。成熟后有已有库存就自动续种，不要求先收取；没有库存就等待，不自动补货。已有存格可能连续消耗多包：同一习惯存六格且有两包种子，明确播种后可连续完成两轮。补货按等待时间、再按个人创建顺序供给已等待的习惯，查看顺序不改变分配。
- 成熟成果留在待收篮，不腐坏；逐习惯收取只进入本人仓库。H01 没有出售，收取不会增加农场币。旧待收篮和正在生长的新一轮分别显示。
- 失败保留输入；结果未知时用原请求确认，不靠再次新建猜测结果。已成功请求重放原始回执，再读取当前农场；从未成功的旧日请求跨 04:00 后过期，重新记今天须由本人明确提交。

## 云端边界

两个公开 RPC 是业务入口：`get_personal_farm(p_household_id)` 返回已结算的本人快照；`apply_habit_action(p_household_id, p_request_id, p_action)` 执行 H01 动作并保存原始响应。成功请求按原 ID 和原载荷精确重放，换载荷被拒绝；身份检查在回执读取之前。写入成功后单独读取当前状态，不把旧回执中的快照当作最新值。

数据位于私有表，浏览器不直接读写。成员必须属于指定家庭，管理员不能代看或代写；账号重新绑定也不会继承原账号的农场。创建顺序是个人内序号，不暴露其他成员的习惯数量。先取得家庭共享锁、再锁本人成员行，与既有家庭管理保持锁顺序一致；同一成员的操作串行，结算依有效记录的实际截止时间推进，再分配有限种子。

生产时钟来自私有 `clock_timestamp()` helper，没有公开的时钟设置接口或请求参数。只有本地隔离 PGlite 测试覆盖该 helper，以同一 RPC 模拟多日和 04:00 边界；这些结果不代表真人连续打卡，也不替代真实云端 30 秒与浏览器验收。

## 维护与验证

现有脚本如下。模型命令使用已安装的 Blender，生成真实 GLB；普通界面修改不需要重建整个城市。

```sh
npm run test:habits
npm run test:cloud:habits
npm run model:habit-farm
npm run model:verify-habit-farm
npm run model:habit-farm-studies
```

`test:habits` 检查 RPC、客户端、个人城市投影和农场场景。`test:cloud:habits` 经真实 Auth 与公开 RPC 验证当前日、实际 30 秒、私密隔离和请求竞争，会写入隔离测试家庭并产生验收证据；不得指向真实家庭。PGlite 会串行调度本地请求，实际多连接竞争证据以云端测试为准。

H01 云端验收使用本机 `.env.h01-test`：该文件被 Git 忽略，权限为 **0600**，仅配置专用测试家庭和测试账号。本文不列凭据值；缺配置时应停止测试，不能改用真实家庭。不得上传该文件或把服务端秘密放进浏览器变量。

需要浏览器验收时，由执行代理自行启动本地服务并打开 **in-app browser**，无需用户手工启动，也不操作用户 Chrome。本轮使用 5176；先检查端口是否空闲，不停止用户的其他服务：

```sh
npm run dev -- --host 127.0.0.1 --port 5176 --strictPort
```

分别留存桌面/窄屏、真实保存与撤销、实际经过 30 秒后的成长、刷新、身份切换及 GLB 多视角证据。三日成熟、FIFO 和跨界时序的受控时间证据单独标注。

H01 新增迁移已经应用，八份本地与远端迁移匹配；不要为发布重复初始化家庭。后续数据库变更仍按既有维护流程先核对差异再应用。发布前运行相应回归、`npm run typecheck`、`npm run build` 和 `npm run test:sites`，保留 Sites 输出约定。Web 部署状态及正式应用验收必须单独确认；本地命令通过不等于已经上线。
