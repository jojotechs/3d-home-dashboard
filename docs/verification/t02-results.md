## 本票行为

- 余额与负债分别维护名称、人民币金额；可新增、改名、改金额、移除和撤销待移除。银行、支付宝/微信、公积金以具名余额记录，不增加分类字段。负债必须大于零，余额允许零。
- 金额按整数分字符串传输，草稿合计使用 BigInt，云端使用整数 numeric；净额可以为负。已保存净额与草稿合计独立，输入或失败不会提前更新已保存状态。
- `save_finances(household, changes, request_id)` 接收增改删补丁，每项带自己的预期版本。家庭锁使一次提交的多行变动、版本和完整历史快照在同一事务中提交；不以旧整表覆盖新记录。不同行修改可同时保留，同行陈旧版本返回 PT409。
- 创建者不变，最近修改者与时间独立显示，时间按北京时间。移除使用保留版本的退役记录，当前快照不含退役项目，过去历史仍保留原名称、金额和归属；旧创建请求无法复活已移除的身份。
- 相同请求重试只确认原结果，确认后再读当前账。无变动提交不增加历史、版本或更新时间。旧 `save_balance` 入口转入同一实现，并兼容 T01 已有重试凭据。
- 关闭、回总览、切换模块、今日事务、退出登录与恢复生活示例都会经过未保存提示。保存中须等待结果；失败保留编辑内容。刷新/关闭标签页使用浏览器离开提示，不持久化草稿。
- 手动读取最新记录保留本地改动并更新云端对照值，随后需点“确认并保存修改”；已被另一成员移除的项目需要放弃该项草稿。不会自动重试或自动合并保存。

## 应用内浏览器场景

本地地址 `http://127.0.0.1:5174/` 连接真实云端。独立测试家庭 `e48c920e-ba1c-421e-bab5-a8fc4d5ae3ac`，角色为“列表管理员”和“共同记账成员”；两者在独立标签页登录。凭据仅在忽略文件 `.env.t02-test`，不提交到仓库。真实家庭未用于写入验收。

1. 管理员新增工资卡 1000.01、支付宝/微信 200.02、公积金 300.03、住房贷款 2000.07。保存前云端净额仍为 0，草稿净额 -500.01；关闭提示“继续编辑/放弃并离开”。继续后保存，12:38:42 云端确认 -500.01，刷新读回一致。
2. 管理员在同次保存中把工资卡调为 900.01、钱包调为 300.02；成员同时从旧快照把公积金改名、调为 310.03。结果 -490.01，三行修改全部保留，成员编辑记录的创建者仍为管理员。
3. 两个会话编辑工资卡同版本。管理员先保存 901.01；成员保存 902.01 和贷款 2001.07 被整笔拒绝，两个输入均保留。读取最新记录后看见云端 901.01，明确确认后保存成功。
4. 成员同次将工资卡改名并移除公积金；待移除状态提供撤销，保存后当前列表移除该项，历史由同一公开 RPC 核验。

环境现象：初次全表面浏览器发现超时，直接打开应用内预览后恢复；第一次浏览器登录失败，重试成功。云端接口登录正常。未把这些重试当作确定的产品缺陷。浏览器工具没有断网控制，此票未声称已完成浏览器断网注入；失败保留通过真实版本冲突验证。
