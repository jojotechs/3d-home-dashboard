# 习惯农场 · 商店与品种扩展设计

2026-10-20。状态：发现阶段的研究与方案，不是已实现功能或最终规格。用户第六轮明确要求类似《牧场物语》的种养→收获→出售→购买循环，并强调代码可扩展、可持续新增品种。最新确认与待选问题以 [访谈记录](habits-discovery.md) 为准。

## 已确认的基础

- 每位成员只经营自己的习惯农场，一条习惯对应独立种养进度，六个展示位置可切换；公开记录不产生家人共同贡献。
- 日/指定日达标给一格；周任选 N 天每个达标日一格、当周最多 N 格；周/月累计目标达标给三格、同周期一次。三格产生一轮成熟成果，余量保留；部分进度/超额不额外发放成长。
- 只记录当前习惯日，30 秒撤销后锁定。尚可撤销的成长不能先被领取、出售；不会因为商店存在而允许改历史。
- 成熟成果保留在待收篮，后续成长继续下一轮；本人手动收取，也可一键收取。领取后的产物进入出售环节。
- 设施永久保留、漏打不造成枯萎或拆除；游戏币购买替代之前建议的自动里程碑建设。
- 第七轮确认作物每轮耗一包种子、动物一次购买长期持有，保留一种免费基础作物，缺种子时成长保存。品种价格和净收益有差异，仍三格成熟；设施只改善外观，不增产、不加速、不提高售价。具体价格表由代理设计。

## 当前代码事实

- `src/city-state.mjs` 是本机示例任务和节点显隐，没有正式种养库存、金币或交易；不能据其预设成长给真实用户发物品。
- `modeling/refined_districts.py` 的 `farm()` 按位置索引确定六种作物/动物、标牌和地面附件，72 个节点代表展示数量；不是可以动态注册品种的通用地块。
- `modeling/finance-levels.json` 与 `src/finance/growth.mjs` 已分开业务状态和资源选择，可参考其职责划分。
- `src/finance/FinanceDistrict.mjs` 已集中管理区块模型、灯光与资源释放；`src/finance/useFinanceProjection.ts` 只使用当前账号的已授权云状态。农场可采用同样的所有权边界，不照搬财务等级算法。
- `src/activities/PedestrianActivities.mjs` 提供场景持有、构造注入的活动注册；未来农场可提供浇水、收取、喂养和逛店地点。视觉小人不能直接生成业务产物、出售库存或发币。

## 扩展边界方案

| 模块 | 负责 | 扩展约束 |
| --- | --- | --- |
| 品种目录 | 稳定品种标识、名称、生产类别、产出物引用、资产引用 | 新增普通品种用目录条目表达；不把品种名写进核心交易分支。 |
| 成长与生产规则 | 已确认的成长格计算、成熟/待收状态、每轮产出、生产者是否保留 | 复用少量明确的策略。仅新增真正不同的生产机制时扩展实现，不先造任意脚本系统。 |
| 物品目录与报价 | 种子/产物/动物/设施的物品类型、可堆叠或永久持有方式、买价/卖价与上架状态 | 报价由云端判定，不能从 GLB 名称推导；报价与品种生产属性分开。 |
| 个人经营状态 | 种养实例、待收成果、物品库存、长期持有物、农场币与交易回执 | 领取/出售/购买分别原子完成，重试不重复发物、扣物或扣币；不接入家庭人民币账本。 |
| 展示投影与资产目录 | 从已授权云状态得到六个当前展示位，选择 GLB、阶段、产物、动画和交互锚点 | 加载/切组/释放集中管理；模型自身不判定达标、余额或成交。 |

对象通过稳定接口和构造注入组合。新增同类品种无需重写打卡、成熟、收取、售卖和购买流程；新品种有新几何时，仍需要制作真实模型、定义阶段并验证，不能承诺只加一段配置就凭空生成完成资产。

目录使用稳定 ID 和版本；新价格不改变已成交回执，修改/下架品种不能让用户已拥有的库存、动物、设施或待收成果失去定义。每轮产物保留对应品种/产出信息，换品种不会把旧待收篮转成新高价产物。

## 模型资产扩展方案

- 保留农场的城市位置、整体布局、米制尺度以及既有建筑品质；将种养内容与必要的局部地面/围栏/标牌拆成独立 GLB 组合。
- 统一局部原点、允许占地/高度、成长阶段节点、产物节点和行人交互锚点；新组合可以挂到任一展示位，不由第几个地块决定品种。
- 原有 12 个显隐槽不等于成熟所需天数、库存上限或种植数量。
- 只加载当前展示所需的组合，处理切组/换账号/迟到加载/释放，沿用已有夜间、暂停与减少动态效果约定。
- 增品种时校验目录引用、生产规则参数、价格与产出关系、真实 GLB 节点和尺寸；以新增一个同类品种且不改通用流程作为扩展性验收。

## 第七轮确认的经营方案

### 购买模式

作物种子为耗材，开始一轮消耗一包；动物为长期拥有的生产者，收取只领取蛋/羊毛等，不消耗动物。保留一种免费基础作物，避免花完币后无法继续经营；种子缺货时有效成长保存，第八轮已确认使用已有同品种库存自动续种。

购买后永久解锁所有作物、之后不耗种子的候选方案已被排除。自动消耗已买的种子与自动花币补货是不同动作；当前未授权自动花币。

### 品种与设施收益

- 品种采用不同买价、产物售价和净收益；高级品种净收益更高、外观不同，仍遵守三格成熟。具体价表由代理设计，不改变已确认的习惯成长公式。
- 设施只提供永久真实外观，无产量/售价加成，不改变成长速度或习惯目标。
- 首版报价拟固定且明示；领取后入本人仓库、选数量出售，再用币购买商品，不把点击收获等同自动出售。首批商品和价格作为可审阅的具体方案列出。

首版已拟定并做算术核对的商品/设施价格、再投资路线及缺货/归档场景见 [商品与价格草案](habits-economy-draft.md)。这是用户委托并已随完整规格确认的设计，不是既有账户数据。

### 第八轮确认的续种、布局与提醒

Q26 已选择使用已有库存自动续种：同品种种子足够时继续下一轮，缺货保存成长；不自动花币补货、不擅自切到免费作物。首次播种和换品种由本人选择。动物长期持有，产物待收不阻止下一轮。

Q27 已确认未分配成长可用于同一习惯下一次选择的新品种，已有轮次与产物不变种；Q28 已确认设施安装在预设位置；Q29 已确认首版仅应用内今日清单和未完成提示。完整流程与验收要求统一见 [已确认规格](../specs/habits-farm.md)。

## 后续应覆盖的验收

后续分片需从首个业务闭环验证真实云端与应用内浏览器：本人成长→待收→收取→库存→出售→余额→购买→真实模型变化。授权和重试用同一云端业务边界验证，覆盖跨账号读取/写入、重复领取、重复售卖、并发购买不足余额或库存，以及 30 秒撤销与成熟顺序。不能只做本机商店示例后延迟云端验证。
