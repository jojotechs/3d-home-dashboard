# 习惯农场纵向拆票独立审阅稿

2026-10-20。用户已整体确认方案并授权定稿与拆票。本文件保留拆分时的独立审阅过程；最终逐票正文、实际 Issue 与依赖状态以[任务发布索引](habits-ticket-breakdown.md)为准。本稿不代表功能已实现或验收通过。

依据：[完整方案](../specs/habits-farm.md)、[商品和算例](habits-economy-draft.md)、[Issue 工作约定](../agents/issue-tracker.md)。HF 编号引用完整方案的验收编号。票名中的 H01–H18 是本稿的临时编号，不冒充已存在的 Issue 编号。

## 拆分原则与共同验收

- 每票交付一条可演示的用户行为，包含所需云端业务边界、授权、页面和实际模型投射，不横拆“先数据库、再后端、最后前端”。目录、时钟、去重和模型契约随首条使用它们的路径建立。
- 首票就接现有 Vercel、Supabase、账号和家庭身份；新习惯业务从空状态开始，不导入 demo。只使用隔离测试家庭写验收，不向真实家庭植入测试数据。不另造认证系统、付费资源或管理后台。
- **全部 E2E 使用 in-app browser；不操作 Chrome。** 每票独立完成桌面及适用窄屏流程、云端刷新验证，记录日期、部署/代码版本、账号角色、结果及证据；不得把这些工作推给 H18。
- 每条新增写路径当票验证权限、相同请求重放、未知结果及并发守恒；失败保留输入，不用本机日期、余额或库存判断替代云端。金额、成长、30 秒和竞争条件通过同一公开业务边界精确验证，不要求浏览器工具模拟所有网络故障。
- 时间证据分开：真实浏览器验当前习惯日保存、实际 30 秒、模型及刷新；三日、周/月交界用隔离测试部署的受控时钟和同一业务边界验证，明确标成模拟时间。不能在线等待三天，不能把测试造历史描述成真人连续打卡；测试时钟不得成为生产请求参数或后门。
- 涉及模型的票交付真实 Blender/GLB、可复现命令、实际尺寸/通路检查和多视角证据。保留米制尺度、农场边界、七街区及其他已批准模型；每个模型附所需阶段、局部坐标和活动锚点。
- 直接依赖只列真正需要的已交付能力，不重复写传递依赖。发布后开始每票仍须读取 GitHub 实际 blocker 状态；本稿不推定任何未来票已完成。
- 同一 HF 可跨票逐步完成。下表和每票列的是覆盖范围，只有全部相关路径完成才能宣称该 HF 整体通过。

## 候选切片

### H01 · 从空账户记录每日习惯，并在真实雏菊地块看到成长

- **端到端交付：** 已有家庭成员从应用级入口登录，创建仅自己可见的每日打卡型习惯，按数量领取免费雏菊种子，明确播种；真实云端记录、30 秒撤销、成熟结算和逐习惯收取接通。一块实际 GLB 展示刚播种、1/3、2/3与待收；雏菊库存允许基础同品种自动续种，缺货存格。先提供习惯列表和当前选中的一个真实种养位；六位分组在 H13。
- **直接阻塞：** 无新的习惯票；执行前核实既有认证、家庭身份和云端部署可用。这是现有能力检查，不另开基础设施空壳票。
- **覆盖：** HF01、HF02（私密授权基础）、HF03（打卡）、HF05、HF06、HF08（按日与三格）、HF09（基础同品种）、HF11（逐习惯入库）、HF14、HF15、HF16、HF17。
- **重要验收：**
  - 新身份 0 币、空习惯/库存/种养；旧本机 demo 不进入云端，也不通过新记录累计住宅成长。跨成员/跨家庭 ID 请求被拒绝，管理员无私密例外。
  - 当前日保存后云端确认；30 秒内撤销有效、刷新不延长窗口，过期不能删除；已撤销记录不产成长，预览不能收取。
  - **真实 in-app browser：** 当前日打卡、实际等待撤销期后 GLB 0→1 格，刷新读回；撤销分支用另一条当前日习惯验证。保留登录返回原入口和错误输入。
  - **受控时间的同业务边界：** 三个应做日各一次达标恰好成熟一份，领取入库、重复领取不增货；明确此证据不是三天真人操作。实际 GLB 的其余阶段同时做模型与多视角验证。
  - 建立原请求回执、云端日界线、版本化迁移及最小模型契约；未知请求重放不重记、不改归属日。

### H02 · 分次记录阅读数量，并查看可解释的当日与历史明细

- **端到端交付：** 创建每日计量习惯，支持分钟/小时/次和自定义单位；追加本次数量、显示合计与达标状态、30 秒逐次撤销、历史只读。使用 H01 雏菊完整表现达标成长，计量未达标不能冒充农场成长。
- **直接阻塞：** H01。需要已有授权记录、稳定成长、真实地块和回执，避免另造计量专用状态系统。
- **覆盖：** HF03、HF05、HF06、HF08、HF16、HF17。
- **重要验收：**
  - 10+15 分钟显示25；超额继续保存实际量但不额外发格，无覆盖总量或历史编辑后门。
  - 达标依赖多笔记录时，只有不可撤销的有效数量足够才发格；撤销一笔不能留下提前生成的产物。
  - 目标和追加量使用明确精度，单位展示不改变原量；错误、丢响应、重复追加和两窗口竞争通过同一云端边界检查。
  - **真实 in-app browser：** 新建阅读、分次追加、撤销一笔、真实等待后看到业务进度和 GLB 成长分离，查看历史并刷新；窄屏不靠悬停操作。

### H03 · 按指定日期记录习惯，休息日看到下一次安排

- **端到端交付：** 每日、指定星期、每 N 天、每月指定日期/月末可配置、预览和实际记录；今日入口显示应做项或下次日期，真实打卡驱动已有雏菊。
- **直接阻塞：** H02。需同时覆盖打卡型和每日计量目标，复用准确追加和历史。
- **覆盖：** HF04（按日安排）、HF05、HF08、HF16、HF17。
- **重要验收：**
  - 每 N 天以开始日锚定；每月31日不存在时跳过，月末是另一明确选项。设置预览接下来三个日期。
  - 非应做日没有记录入口，云端同样拒绝；北京时间04:00和真实操作时间不受光照预览影响。
  - **真实 in-app browser：** 配置包含当前日的星期安排并记录；配置不含当前日的安排，显示下一次日期而不允许保存。
  - 月末、闰年、间隔和跨04:00用受控时钟验证；不修改真实时钟或给生产增加自选历史日入口。

### H04 · 每周任选 N 个达标日，准确区分“天数”和“次数”

- **端到端交付：** 创建每周任选1–7天的打卡/计量习惯；每日目标、周达标日计数、当周剩余天数与成长可见，不固定到指定星期。
- **直接阻塞：** H02。需每日独立达标、计量和撤销机制；不依赖 H03 的日期排程，允许并行。
- **覆盖：** HF04（每周 N 天）、HF05、HF06、HF08、HF16、HF17。
- **重要验收：**
  - 每周3天、每天30分钟：一天90分钟仅算一天和一格；达成3天后还能记录第四天，但当周不超过3格。
  - 首个不完整周不折算目标、未完成不冒充完整失败周；撤销重算当日和本周状态。
  - **真实 in-app browser：** 当天分次达到每日门槛，看到周计数只增一天，GLB只加一格，刷新一致。
  - 多日、周一04:00及封顶通过受控业务时钟验证，证据不冒充跨周真人使用。

### H05 · 周/月累计目标当天达标，完成真实浏览器成熟收取闭环

- **端到端交付：** 创建周/月累计数量目标；各归属日累加，周期未完显示进行中，达到完整目标发3格。通过真实已播种雏菊，完成当天记录→成熟→收取入仓。
- **直接阻塞：** H02。需要追加量、精度、撤销和真实种养，不依赖 H03/H04 的其他排程。
- **覆盖：** HF04（周/月累计）、HF05、HF06、HF08、HF11、HF16、HF17。
- **重要验收：**
  - 同周期最多发3格；部分与超额不额外发格，首个不完整周期达到完整目标仍可获得成长。
  - **真实 in-app browser：** 用真实当前周期创建小目标，分次达到它，实际等待30秒后成熟，点击收取并刷新仓库。这补全 H01 不能在当天真人完成的三格收获证据，不伪造过去记录。
  - 部分进度、月长、跨周/月04:00和重试边界通过受控时钟；累计目标不会每天被标红为失败。
  - 未领取旧成果时再次获得合法周期成长，旧篮与新进度相互独立；多周期模拟证据单列。

### H06 · 修改未来规则、归档并恢复，保留既有记录与成长

- **端到端交付：** 习惯详情显示当前与待生效规则；可修改/取消唯一待生效版本；归档列表查看历史、当前轮和待收，恢复后继续合法记录。支持所有已交付周期与完成方式。
- **直接阻塞：** H03、H04、H05。需覆盖日/周/月不同结算周期和真实历史，不把版本切换仅实现成每日特例。
- **覆盖：** HF04（版本历史）、HF05、HF06、HF07、HF08、HF11（归档收取）、HF16、HF17。
- **重要验收：**
  - 按当前规则确定次日/下周/下月生效点；单位换量纲分段，不重释旧数量、不重发成长。目标变化后的首段周期标注正确。
  - 30秒到期前归档：有效成长留在原习惯未分配余额，旧轮和新轮都冻结；恢复先继续旧轮。到期后才归档：先结算已生效事件，不因延迟读取吞掉成熟/续种。
  - 原成功请求在归档或规则变化之后重放，仍返回原结果；身份授权失效则拒绝读取；同ID不同载荷拒绝。
  - **真实 in-app browser：** 编辑未来规则、归档后收取既有成果、恢复并刷新；另做当前日保存后立即归档、实际等待30秒及恢复的实景验证。

### H09 · 番茄换种与有限库存续种，存下的成长有明确去向

### H11 · 买一只鸡长期产蛋，并安全移动与归档恢复

- **端到端交付：** 180币购买一只鸡，仓库显示可用/占用，分配到习惯后每三格产一份30币鸡蛋；成年鸡模型常驻，蛋表现阶段变化。实现动物移动、下一轮改种和动物习惯归档恢复。
- **直接阻塞：** H09。需成熟交易、换种、成长保存和归档结算；本票引入第一个永久动物生产策略，而非预先空建抽象系统。
- **覆盖：** HF06、HF07（动物归档）、HF08、HF10（动物）、HF11、HF12（鸡）、HF14、HF15、HF16、HF17。

  - 归档时仍在30秒内的记录只在到期后进入原习惯未分配余额；用真实时间分别验证到期前/后移动或归档的顺序。
