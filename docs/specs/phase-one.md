# 一期规格：云端读写、家庭认证与五阶段十级财务市区

## Problem Statement

我希望把家庭财务管理变成一座可以进入、操作和持续成长的小城，让存款的变化带来可见的反馈。现有原型已经有真实三维建筑和互动，但财务只是保存在单个浏览器里的示例数字：家庭成员无法登录共享真实记录，换设备不能继续使用，不能追溯谁录入或修改了金额，三档建筑也无法表达我期待的十级成长。

现有财务模型按历史最高金额保级，不能如实反映当前储蓄状态；建筑和街景仍偏素，高等级缺少明显的豪华与繁荣感。我需要先把财务市区真正用起来，从第一个功能就验证云端持久化、认证和权限，而不是所有地区完成后才补后端。

## Solution

交付面向我自己家庭的第一版真实财务市区：使用独立账号登录，在城市中打开财务面板，手动管理银行、支付宝/微信、公积金余额与负债，点击保存后写入云端并留下可追溯历史；刷新或换设备仍读取同一份家庭财务账。

储蓄净额决定当前财务等级及模型，可立即升级或降级。五个发展阶段包含十级清晰可辨的真实建筑，各级都有精细街景和昼夜氛围，最高两级加入豪华地标、射灯、赛博全息广告与飞行广告。财务图鉴分别显示当前、历史已达成与未达成状态；未达成级置灰上锁，但允许标明状态后试看，激励继续储蓄。

第一版采用 Vercel 网页托管、Supabase 数据库与认证、Resend 邮件，免费优先。现有其他区块保留原型用途，后续分别讨论；本期不扩大为完整记账、资产管理或备份产品。

## User Stories

1. 作为家庭成员，我希望直接从城市中的财务市区打开家庭财务账，以便城市本身就是日常操作入口。
2. 作为操作人，我希望使用自己的邮箱和密码登录，以便共享设备或家庭协作时仍能区分身份。
3. 作为忘记密码的操作人，我希望通过真实送达的邮件恢复登录，以便继续访问家庭记录。
4. 作为初始家庭管理员，我希望以受保护的方式建立管理员身份，以便管理家人的加入和权限。
5. 作为管理员，我希望通过邀请让家人加入，以便第一版只服务获邀的家庭成员。
6. 作为管理员，我希望邀请过期时能得到提示并重新发送，以便家人可以完成加入。
7. 作为管理员，我希望授予或移除财务访问权限，以便决定谁能查看和修改共享财务账。
8. 作为家庭管理员，我希望家庭成员与登录账号分开表达，以便没有账号的家人也可以作为家庭成员存在。
9. 作为获财务授权的成员，我希望查看和编辑完整共享明细，以便共同维护同一份家庭财务账。
10. 作为财务数据的使用者，我希望未获授权者看不到金额、历史或能推断财富的等级信息，以便共享城市不会泄露家庭财务状况。
11. 作为操作人，我希望退出或切换账号后不残留上一个账号的财务数据，以便账号边界清楚。
12. 作为首次使用者，我希望空数据库从 Lv.1 开始且没有虚构历史，以便真实记录从我自己的输入开始。
13. 作为现有原型使用者，我希望演示金额和历史峰值不会自动进入真实家庭账，以便示例不污染实际数据。
14. 作为记账的家庭成员，我希望在余额列表中填写银行、支付宝/微信和公积金，以便满足目前家庭的简单统计需求。
15. 作为财务数据的使用者，我希望界面把这些金额称为储蓄净额，以便不会误认为它是全部家庭净资产或随时可花的钱。
16. 作为记账的家庭成员，我希望单独填写正数负债并由系统扣除，以便容易理解余额与负债的关系。
17. 作为记账的家庭成员，我希望增加、修改名称和金额、移除余额或负债项目，以便随实际情况维护列表。
18. 作为记账的家庭成员，我希望金额按人民币分准确记录，以便合计和等级门槛不会因小数误差变化。
19. 作为财务数据的使用者，我希望负债超过余额时能显示负净额并保留基础城市，以便仍能如实记录当前情况。
20. 作为编辑者，我希望输入完成后手动点击保存，以便可以一起调整多个项目，而不会每改一个输入框就改变城市。
21. 作为编辑者，我希望保存前可以查看草稿合计，同时真实等级保持原状，以便分清正在编辑和已经保存的数据。
22. 作为编辑者，我希望一次保存中的多项变动一起成功或一起失败，以便转账两端不会只生效一半。
23. 作为编辑者，我希望保存失败后保留输入和编辑状态，以便修复连接后重试而不用重填。
24. 作为编辑者，我希望重复提交同一次更新不会生成重复历史，以便网络重试不会污染记录。
25. 作为编辑者，我希望没有实际变更的保存不制造历史，以便历史只包含有效更新。
26. 作为编辑者，我希望关闭有未保存修改的面板时能选择继续或放弃，以便避免误丢输入。
27. 作为协作成员，我希望修改不同项目时保留彼此的结果，以便不会被另一个人的旧表单覆盖。
28. 作为协作成员，我希望同一条记录发生冲突时收到提示并保留输入，以便核对后再提交。
29. 作为家庭成员，我希望刷新、重新登录或换设备后看到相同记录，以便家庭财务不依赖某个浏览器。
30. 作为家庭成员，我希望每条余额和负债显示原创建者，以便知道是谁最初录入。
31. 作为家庭成员，我希望另行看到最近修改者和时间，以便知道记录后来由谁更新。
32. 作为家庭成员，我希望每次财务更新形成带操作人和时间的历史，以便了解家庭储蓄的变化过程。
33. 作为家庭成员，我希望从有效历史查看净额趋势和历史最高，以便了解长期积累。
34. 作为发现错误的编辑者，我希望随时纠正错误历史并保留修订归属，以便趋势和历史最高反映有效记录。
35. 作为编辑者，我希望修正旧历史不会覆盖之后的财务更新，以便纠错不会把当前状态退回过去。
36. 作为编辑者，我希望修正最近一次有效更新时同步纠正当前净额和城市，以便当前展示始终一致。
37. 作为家庭成员，我希望移除当前项目后仍保留历史中的名称、金额和归属，以便过去的变化仍可理解。
38. 作为家庭成员，我希望保存后按当前净额立即确定财务等级，以便城市表达现在的家庭状态。
39. 作为家庭成员，我希望达到门槛时可直接跨越多个等级，以便首次录入或较大变化能被准确表达。
40. 作为家庭成员，我希望净额下降时城市立即降级且没有缓冲，以便普通支出也能在城市中体现。
41. 作为家庭成员，我希望历史最高独立展示而不阻止当前城市降级，以便区分过去成果与现在状态。
42. 作为希望增加储蓄的成员，我希望看到下一级门槛和尚差金额，以便有明确的下一目标。
43. 作为家庭成员，我希望达到 Lv.10 后仍能保存金额与历史，以便满级不影响继续使用。
44. 作为城市使用者，我希望十级拥有可辨识的建筑体量、类型和公共空间，以便每次成长都有实际变化。
45. 作为城市使用者，我希望低等级也有精细建筑、店面和生活氛围，以便从初始级就愿意停留和使用。
46. 作为城市使用者，我希望 Lv.9–10 明显更豪华繁荣并有射灯、全息与飞行广告，以便高等级具有值得期待的成果。
47. 作为城市使用者，我希望高级街区在白天和夜晚都成立，以便视觉品质不依赖夜光效果。
48. 作为城市使用者，我希望升级或降级有简短反馈，以便理解保存带来的变化而不被长演出打断。
49. 作为财务图鉴使用者，我希望当前等级被突出显示，以便知道真实城市正处在哪一级。
50. 作为财务图鉴使用者，我希望历史已达成等级保持彩色收录，以便正常降级后仍能回顾成果。
51. 作为财务图鉴使用者，我希望未达成等级置灰加锁并显示目标，以便清楚区分已达成与未来目标。
52. 作为财务图鉴使用者，我希望锁定级仍可明确标记后试看，以便了解继续储蓄会带来什么变化。
53. 作为财务图鉴使用者，我希望离开预览后返回真实等级且不修改金额或解锁成果，以便预览不会影响家庭数据。
54. 作为财务图鉴使用者，我希望错误高额历史被纠正后重新计算收录，以便图鉴也反映有效成果。
55. 作为对动态敏感的城市使用者，我希望飞行广告和扫动射灯遵守暂停与减少动态设置，以便舒适地查看城市。
56. 作为城市使用者，我希望视觉预览、暂停和加速昼夜不改变真实业务或行程时间，以便看效果不会触发错误事件。
57. 作为已有原型使用者，我希望住宅与健康的永久设施、双车独立状态和交通动画继续正常工作，以便财务升级不破坏其他区域。
58. 作为家庭自用者，我希望使用普通云端部署并优先免费服务，以便尽早开始实际使用且能掌握成本。

## Implementation Decisions

### 1. 交付边界与现有原型衔接

- 第一个业务切片就包含认证、真实云端读取、保存和重新读取，不能以本地 mock 代替持久化验收。第一批使用者是用户自己的家庭；业务数据以家庭隔离，并保留以后支持更多家庭的结构。
- 保留 React、Vite、Three.js 和真实 Blender 生成的 GLB 路线。继续使用城市选择、财务面板、等级预览和现有场景可见性能力；不重写成另一套前端或用截图代替可交互几何。
- 真实财务从空库开始，基础视图 Lv.1，不迁移、预填或读取演示金额、峰值和奖励，不制造零金额历史记录。首次真实保存可直接跨级。
- 其他地区保留清楚标识的原型行为，财务接入不把旧的“恢复示例”操作变成真实云端数据重置。旧财务面板的假定金额、固定月储蓄/百分比及保级文案应移除或由已确认真实数据替代。
- 保留既有 Sites 托管包装及输出契约，使正式构建仍可按原方式交接。

### 2. 模块职责与公开业务入口

- 认证及家庭权限负责会话、邀请、成员关联和授权。登录身份与家庭成员独立关联，成员可以没有登录账号；初始管理员管理邀请和财务授权，其他获授权成员可读写整个共享账。
- 财务应用入口提供读取家庭财务、提交一组财务修改、读取历史和纠正历史的业务操作。财务面板与三维场景消费经授权的数据及派生展示结果，不自行组合数据库业务调用。
- 金额、储蓄净额、等级、历史峰值及图鉴状态由可确定的领域计算表达；Supabase 读写与业务计算分离。复用现有纯状态/可见性测试方式，不另造多层可替换接口只为测试。
- 渲染层接收实际等级和暂时预览等级，并统一选择对应建筑与氛围。预览状态不进入真实财务保存或历史链路。
- 新增测试入口以整个可用网页及其实际使用的云端业务接口为中心；身份绕过、重试和并发从同一公开边界验证，不逐个私有组件或内部函数建立契约。

### 3. 数据、归属与计算

- 业务记录使用稳定自有 ID、家庭归属、创建者、最近修改者、创建/修改时间和必要版本。客户端不能自报可信操作者或绕过家庭归属；服务器根据已认证身份与成员关系确定。
- 当前财务项目分为余额与负债两类，各自有可编辑名称和金额。余额覆盖银行、支付宝/微信、公积金，初版不增加复杂金融分类。负债输入正数，合计时扣除。
- 所有金额按人民币整数分精确存储、校验、比较和传输；储蓄净额为余额合计减负债合计，可以为负。拒绝无效金额，不依赖浮点误差决定门槛。
- 储蓄净额不是完整家庭净资产，也不是可随时支配现金。公积金计入这一项目特定指标，不另加流动性或投资评分。
- 财务历史记录保存该次完整财务状态、净额、当次操作人及时间，并保留理解过去记录所需的名称、金额和创建者归属。当前项目移除后，历史仍可读取。
- 原创建者不因修改而变化；最近修改者与当次财务更新的操作人分别记录。创建者用于追溯，不决定资金所有权或私密可见性。
- 时间点统一存储，界面按北京时间显示；视觉时钟不改变记录时间。有效历史用于趋势、历史最高净额和历史最高财务等级。
- 业务表、约束与访问策略通过版本化迁移管理，测试家庭和真实家庭数据隔离；不引入事件溯源平台或备份服务。

### 4. 手动保存、失败与并发契约

- 编辑是面板内草稿；可显示草稿合计，但保存成功前不改变实际财务等级。点击保存才提交，仅云端确认后更新实际数据、历史和模型并显示成功。
- 一次提交仅包含新增、修改、移除的项目及对应预期版本，不能上传旧整表覆盖别人新值。多行修改、历史快照与版本更新在一致事务中完成。
- 对同一记录的陈旧修改执行版本冲突检查，拒绝静默覆盖，保留输入并提示核对。不同记录的并发提交保留双方结果，历史按各次提交时完整、一致的已保存状态产生；不做协作锁定或自动合并产品。
- 同一次更新采用可识别的安全重试语义：响应丢失后重试只能产生一次结果和一次历史，无实际变更不制造新历史。
- 保存失败保留编辑内容与打开状态，实际金额、等级和成功提示不提前变化。关闭未保存面板时提供继续编辑或放弃，不增加离线队列、后台自动保存或跨刷新草稿系统。
- 历史纠错保留修订者和修订时间，并重算有效历史的峰值与图鉴收录。修正旧历史不覆盖后续当前状态；修正最近一次有效更新时同步纠正当前金额、等级和模型。

### 5. 当前等级、历史最高与目标

- 每次成功保存后，当前财务等级取储蓄净额达到的最高门槛，上限 Lv.10。允许跨级升降，不设置缓冲、保护期或只升不降规则；住宅与健康的永久设施规则保持原样。
- 历史最高仅表达有效历史成果，不控制当前模型。纠错后可下降，不作为永久不可更改的解锁缓存。
- 保存导致级别变化时给出简短反馈。展示当前净额、历史最高、下一等级门槛与尚差金额；Lv.10 展示满级，继续记录实际金额和历史。

### 6. 财务图鉴

| 状态 | 判定 | 显示和操作 |
| --- | --- | --- |
| 当前 | 与当前财务等级相同 | 彩色突出显示当前，能返回当前模型并查看进度 |
| 已达成 | 有效历史最高以内、但不是当前级 | 彩色收录，标记已达成，可预览 |
| 未达成 | 高于有效历史最高 | 置灰加锁，显示门槛/差额，仍可试看并标明未达成与预览 |

- 达到高等级时，以下级别一并视作已达成。正常降级只改变当前标记和实际城市，已达成收录保留；错误历史被纠正且不再有有效依据时重新锁定。
- 空库 Lv.1 是基础可见状态，其余未达成，不因此伪造历史最高记录。
- 例如保存 52 万元达到 Lv.7，之后保存 46 万元时实际城市降至 Lv.6，Lv.7 保留已达成；如果 52 万元是错记且更正后没有其他有效 Lv.7 记录，Lv.7 重新锁定。
- 图鉴能预览十级；离开预览恢复当前实际级，预览不写入金额、历史或达成状态。

### 7. 五阶段十级建筑与氛围

- 十级必须是多角度可辨的真实几何与完整街区构图，不能只改变高楼高度、颜色或发光强度。所有级别都提高建筑和街景细节，低等级保持完整品质。
- 保存获批 v0.4 繁荣原始几何；原三套建筑作为新 Lv.1/5/7 的基础，追加细节与新变体，旧成品不自动满足本次提高后的质量要求。高级后继模型独立制作，保留原始参考。
- 保留 60×44 m 财务地块、60 m 建筑限高及统一米制比例。其他获批地区布局、六米道路、车辆/人物比例及机场和铁路空间保持一致。

| 等级 | 建筑与街景要求 | 氛围要求 |
| --- | --- | --- |
| Lv.1 | 精细低层街角，瓦片、檐口、窗框、橱窗、路缘、花箱与咖啡外摆 | 小型暖色招牌、檐下灯与少量营业活动 |
| Lv.2 | 大屋顶室内市场、储蓄所侧翼、结构完整的雨棚、摊位与连贯铺装 | 灯串、成组遮阳棚与顾客，形成明显商业节点 |
| Lv.3 | 成排两三层底商、骑楼/阳台、招牌支架、差异化入口与屋脊 | 挂旗、橱窗暖光、自行车和配送活动，沿街营业更连续 |
| Lv.4 | 红砖转角楼、拱顶商业廊、栏杆、橱窗格栅与入口饰面 | 商业招牌、街角展示和廊下灯光，形成热闹步行商业街 |
| Lv.5 | 中层区域中心，石材基座、幕墙竖梃、门厅、台阶与公共庭院 | 小型行情显示带、候车设施、喷泉与办公人群；显示内容为原创视觉装饰，不接入行情服务 |
| Lv.6 | 约 28–32 m 退台商务楼、绿化露台、遮阳构件、服务入口与完整屋顶设备 | 建筑灯带、活动广场、小型数字广告和水景 |
| Lv.7 | 在原繁荣几何基础上细化门厅、石材分缝、金属框架、裙房店面与广场家具 | 立面洗墙光、精品橱窗与分层广场灯光，呈现成熟金融商业核心 |
| Lv.8 | 高端退台变体、屋顶花园、露台会客区、玻璃雨棚与高品质水景 | 数字立面、适量射灯与地面活动装置，增加高级商业密度与秩序 |
| Lv.9 | 原创错层地标群、金属/石材/玻璃分层、空中庭院与高品质商业裙房 | 明确加入赛博全息广告、受控移动射灯和小型飞行广告载体，显著豪华繁荣 |
| Lv.10 | 独立终级轮廓、精细冠部/观景空间、多层景观与连贯公共空间 | 更丰富的全息层次、飞行广告路径、光束与建筑光秀，整体繁荣程度显著超越 Lv.9 |

- 白天靠建筑、材料、载体和公共空间体现品质，夜晚加强暖窗、立面光、广告与射灯，不能仅夜景可辨。
- 全息与广告内容原创；飞行广告具有实际可移动载体，例如无人机广告架或小型飞艇。采用财务区内独立路径，检查与建筑、镜头、机场/铁路动画的空间关系，不复用真实行程调度。
- 氛围随当前显示的视觉等级选择，不增加财务活跃度评分。动态图景使用独立视觉时钟并遵守暂停/减少动态设置；静态灯光仍可保留，真实行程时间继续推进。
- 场景灯光、广告、飞行物和更新器与建筑统一启停。降级、预览退出和卸载后不残留其他等级效果；隐藏等级停止动态更新，避免持续加载或更新全部等级的重动态资源。
- 广告使用合适的专属材质，复制时保留发光及必要着色状态，不破坏现有车辆暖窗。优先共享几何/材质，控制同时产生阴影的移动灯光；不要求所有光束采用高成本真实体积光。
- 模型清单、等级规则、预览描述、导出与验证同步支持十级，避免旧三档精确可见区间使高等级模型消失。根据实际加载、渲染和内存测量选择资源复用或分级加载方案。

### 8. 认证、权限与云端运行

- 采用邮箱/密码、家庭邀请和邮件找回；第一版不开放公众注册或任意创建家庭。初始管理员通过受保护的初始化流程建立，之后由管理员邀请成员。
- 使用 Supabase Auth 与 PostgreSQL，Vercel 部署网页，Resend 提供可实际送达的邮件。发信域名、DNS、可用项目和环境配置在实施时核实；服务商选择不代表已经配置完成。
- 使用服务器授权、数据库权限与行级访问策略共同保护当前记录、历史、汇总、等级和成员权限。管理邀请和授权只允许管理员操作；成员账号不获得云平台管理权限。
- 无财务授权时只显示固定中性财务建筑与权限提示，不能通过接口、当前模型、图鉴当前标记或历史收录/锁定状态推断家庭真实财富。公开静态模型本身不包含家庭数据。
- 移除权限后后续服务端读写立即被拒绝；保留过去创建者/修改者归属。退出与账号切换清除上一用户的内存财务数据；真实财务不写入演示持久化存储。
- 管理凭据与 SMTP 密钥仅存在受保护环境；公开仓库不包含真实家庭数据或秘密。使用免费服务优先，任何必要付费另行讨论。

## Testing Decisions

测试入口已由用户在本次 to-spec 明确确认。好的测试从使用者或调用者可观察的结果判断正确性：金额、记录、归属、权限响应和实际可见模型；不绑定私有函数、组件内部状态、数据库调用顺序或装饰物固定数量。

### 主要入口：真实网页及其云端业务边界

- 新增一个贯穿实际浏览器、认证与真实云端业务入口的验收场景组，作为主要高层测试入口：空家庭登录 → 读取 → 新增/编辑余额与负债 → 保存 → 刷新/另一设备或账号读取 → 等级与模型一致变化。关键验收不能全部替换为 mock 服务。
- 对同一云端业务入口直接发起无授权、跨家庭、伪造归属、陈旧版本和重复请求；验证拒绝或成功后的外部结果。直接接口验证补足单靠 UI 隐藏无法证明的权限与并发行为，不另加测试专用业务 API。
- 测试家庭身份覆盖管理员、同家庭获授权成员、同家庭无财务权限成员和另一家庭成员。数据在隔离测试环境创建和清理，不使用真实家庭账做破坏性验证；测试家庭的准备不开放生产公众注册。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 空库与旧演示数据共存 | 真实财务为 Lv.1、无示例金额和伪造历史，原型值不影响实际账 |
| 邀请、登录、找回 | 邮件实际送达，受邀者完成流程，过期可提示/重发，独立账号身份可追溯 |
| 保存与重新读取 | 多项变动一起提交，刷新、退出重登和另一设备读取相同结果 |
| 创建者与修改者 | A 创建、B 修改后原创建者仍为 A，最近修改者及当次历史为 B |
| 失败与重试 | 失败保留输入且不改实际模型；已提交但响应丢失后重试不重复写入或生成历史 |
| 并发 | 同行陈旧修改报冲突且不丢输入；不同行并发保留双方变化，完整历史保持一致 |
| 历史更正 | 修正旧记录不覆盖更晚状态；修正最近记录同步更新当前；趋势、峰值和收录按有效历史重算 |
| 权限隔离 | 无权限和跨家庭读写均被拒绝；金额、历史、汇总、等级与图鉴达成状态均不泄露 |
| 退出与撤权 | 后续请求按新权限拒绝，切换账号不残留上一人的财务数据 |
| 图鉴 | 当前/已达成/未达成正确；降级保留有效收录，历史纠错可重新锁定；预览不保存，退出恢复实际模型 |

### 复用的快速领域检查

- 沿用已有城市状态和行程状态测试的 Node 内建测试方式，对公开的财务计算与状态输出测试，不为每个辅助函数建立一套测试。
- 覆盖净额计算、人民币分、负净额、每个等级门槛前一分/相等/后一分、多级升降、满级以上、历史最高重算、跨级收录、普通降级与历史纠错的差别。
- 原型已有财务“历史最高决定模型、降级不退”的测试与新规则相反，必须替换财务部分；保留并运行住宅/健康累加设施、双车独立及预览不改变实际状态的既有行为检查。
- 金额密集边界在此快速穷举，浏览器保留代表性的端到端情景，避免每个分值都启动完整浏览器。

### 复用的模型与运行验证

- 沿用现有 Blender 对实际导出 GLB 重新导入、节点可见性、地块边界、限高与米制比例的验证方式。将财务三档假设替换为十级契约，不把旧的固定建筑数量误当新需求。
- 每一级检查白天/夜晚、至少两个相反角度；隐藏级别文字并把财务地块缩至约 200 px 时，相邻等级仍可由建筑和构图区分。渲染图片只作为验收证据，不代替真实模型。
- Lv.9–10 额外审查近景真实构件、总体豪华繁荣感、全息/射灯/飞行广告层次和入口可读性。审图结合实际浏览器操作，不能只通过几何数量或像素快照认定达到艺术质量。
- 浏览器反复升降级、切换预览和退出，检查建筑/灯光/广告同时切换、无残留或持续增长的资源占用；验证动态暂停、减少动态、昼夜预览与真实行程时间分离。
- 复用现有渲染调用数、三角形与平均帧率观测，同时记录加载/解码、模型体积和内存。先建立实际设备与场景基线，再判断回归；当前不宣称新增十级效果已有性能结果。
- 沿用现有交通、昼夜、行程、双车和设施行为检查，验证财务改造没有改变其已批准规则。已有 Sites 测试使用公开请求/响应验证静态资源、路由回退和构建输出，该方式继续保留。
- 实现后运行相关领域/云端权限/保存检查、生产构建与 Sites 包装验证；代理自行运行本地服务器并打开预览，记录实际结果。当前规格整理阶段不运行应用验收，也不声称上述检查已通过。

## Out of Scope

- 中央住宅、健康、农场、车厂、家务、学习及出行等其他地区的正式云端业务接入与额外成长改造；这些地区另行 grill。
- 公众注册、自助创建家庭、个人私密账、复杂成员角色体系，以及本期对外收费功能。
- 银行或金融机构自动接入、逐笔收支记账、账单导入、复杂账户/债务分类、外币换算、投资/房车估值与完整家庭资产分析。
- 强制月度或完整盘点、独立盘点工作流、施工计时、升级付费、长篇首次成长演出、额外财务活跃度模拟。
- 财务永久保级、降级缓冲或保护期，以及把图鉴预览作为达成依据。
- 离线编辑、跨刷新离线草稿、后台自动保存、离线同步队列、自动合并和复杂实时协作。
- 备份、导出/导入、恢复 UI、自动备份、备份调度及完整迁移工具；只保留数据结构和迁移记录的可迁移性。
- 大陆访问质量保证与备案准备作为一期门槛；采用普通云端部署验证实际可用性。
- 第三方广告平台、实时证券行情、从其他游戏复制模型/品牌，以及为了财务氛围扩大地图或改变真实行程调度。
- 在本规格中选定许可证或授予商业许可；源码公开与商业授权选择由独立任务处理。
