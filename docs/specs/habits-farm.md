# 习惯农场规格：个人记录、种养经营与可扩展真实场景

2026-10-20 · **用户已整体确认，规格已定稿；开发尚未开始。**

GitHub 父规格：[Issue #19](https://github.com/jojotechs/3d-home-dashboard/issues/19)，已标记 `ready-for-agent` 并回读核对全文。开发分片及发布状态见 [任务拆分索引](../planning/habits-ticket-breakdown.md)。

用户确认原话：「确认方案，进入定稿与拆票（推荐）」。Q1–Q29、首批价格、操作默认值及测试入口均已确认；下文按标准规格整理，保持已确认的行为不变。父规格用于统领开发分片，不是首个实施任务。

## Problem Statement

当前农场只是本机示例任务与固定种养节点，不能让每位家人安全记录自己的真实习惯，也没有可信的库存、农场币或种养经营。用户希望日常运动、阅读与睡眠目标能带来可见、持续且有约束的农场进展，同时保有个人隐私；新增品种和未来街区活动不应反复改写核心逻辑。

## Solution

### 1. 产品目标与已确认范围

让每位家人用自己的真实习惯经营一座个人农场：**记录习惯 → 达标获得成长 → 种养成熟 → 收取入库 → 出售获得农场币 → 购买种子、动物和设施。**

习惯是生产进度的唯一来源；单纯等待、切换光照、播放小人动画不产币或产物。先做好日常使用闭环与真实云端，再用真实 3D 模型把每次进展表现出来。

| 已由用户确认 | 本次整体确认包含的具体方案 |
| --- | --- |
| 本人记录、逐习惯私密/全家只读；农场只展示本人 | 家人记录独立入口、所有个人计数与模型统一按身份读取 |
| 打卡和计量；参考成熟产品设计周期与跨午夜 | 04:00 习惯日、下述周期组合、追加录入、首个不完整周期 |
| 不补历史，30 秒撤销，之后锁定；目标仅未来变更，归档可恢复 | 云端截止时间、目标版本生效规则、归档恢复与重试细节 |
| 一习惯一种养位、六位分组、三格一轮、待收篮、一键收取 | 首次播种、下轮换种、动物占用、未展示组与归档成果的领取 |
| 种子按轮消耗、动物永久持有、已有库存自动续种 | 首批六品种、六设施、0 币起步、固定价格与库存操作 |
| 存下的成长可用于本习惯新品种；设施固定位置、纯外观 | 明确区分未分配成长与已投入轮次，设施一次购买后安装 |
| 提醒先做应用内、代码与模型方便扩展 | 页面分工、模型契约、云端与实景验收、交付顺序 |

用户已于 2026-10-20 整体确认本规格，包含首批价格、操作默认值、页面流程和测试入口。规格确认不代表功能已经实现或上线。

### 2. 归属、隐私与个人状态

- 习惯属于当前家庭中已有登录账号的本人；只有本人能创建、修改、打卡、撤销和归档。不做无账号习惯成员、代记、代管。
- 每条习惯默认「仅自己」，可改为「全家可见」。公开内容包括名称、目标与规则历史、完整记录和数量/时长，包括归档记录；仅供当前同家庭成员查看。
- 改回私密后，后续云端读取立即拒绝他人访问；已有分享视图在权限刷新时清空。管理员没有私密访问例外，家人不能通过猜测 ID 读取记录。
- 公开不包含仓库、农场币、交易、动物分配或整座个人农场，也不贡献查看者的成长、完成计数或推荐。
- 习惯、农场币、仓库和设施均按当前家庭成员身份隔离，不跨家庭共享。失去家庭成员资格后，原家庭入口和相应读写被拒绝；不把原数据转给其他成员。
- 地图农场、今日清单、顶部习惯计数、地图徽标和首页习惯推荐统一消费本人的数据。新习惯不再通过旧 demo 事件累计给中央住宅或其他街区贡献成长。
- 沿用应用级认证与权限拦截：地图、目录、今日、推荐等所有入口一致；未登录弹独立登录框并记住目的地，未获访问资格弹权限提示。习惯访问不要求财务授权。
- 退出、换账号、换家庭时立即清除前一身份的个人界面、场景内容和待提交操作。迟到请求不能把旧身份数据画回来。未授权时仅保留不含个人状态的基础场景。

### 3. 创建、记录与周期

#### 3.1 创建一条习惯

填写名称，选择完成方式、目标、执行周期和公开范围。默认今天开始、每天执行、仅自己可见；示例名称可辅助理解，但不自动创建运动、阅读或睡眠任务。

创建后得到独立种养位；第一次种什么由本人选择。允许先记录习惯，成长留存，之后再播种。

| 完成方式 | 录入 | 示例 |
| --- | --- | --- |
| 打卡型 | 本人确认完成；一个应做日最多一次有效完成 | 每天运动、00:30 前睡觉 |
| 计量型 | 追加「本次」数量或时长，不覆盖总量 | 阅读先 10 分钟，再加 15 分钟，当日合计 25 |

预设分钟、小时、次，允许页等自定义单位。目标和追加量为正数；保存前显示本次增加量、归属日和合计，避免把追加误当总量。计量达标后仍能追加真实数量，超额不额外给成长。

首版手动录入时长，不加入后台计时器或健康设备自动采集。「00:30 前睡觉」由本人确认达标，点击时间不代表实际入睡时间。

#### 3.2 执行周期

| 周期 | 目标判断与成长 |
| --- | --- |
| 每天、指定星期、每 N 天、每月指定日期 | 每个应做日独立判断打卡或当日计量目标；达标一天给 1 格 |
| 每周任选 N 个达标日（N 为 1–7） | 每天独立判断当日目标；同日最多算一天，当周最多 N 格 |
| 每周或每月累计计量 | 各习惯日数量相加；完整达到周期目标给 3 格，每周期一次 |

- 周从周一开始，月用自然月，日期都由习惯日决定。
- 每 N 天以开始日锚定，不随漏做或恢复顺延；设置时预览接下来三个应做日期。
- 每月不存在的日期跳过，另有明确的「月末」选项。例如选 31 日不会静默移到 30 日。
- 按指定日期执行的习惯只在应做日提供记录入口；休息日显示下次安排。每周任选和周/月累计在当前周期的任一天都可记录。
- 「每周运动 3 天，每天 30 分钟」与「每周累计运动 90 分钟」分别展示；一天 90 分钟不能代替三个达标日。达到每周 N 天后仍可记录其他日的实际完成，但不超过 N 格。
- 中途开始的首个周/月标记为不完整周期，目标不按天折算；达到完整目标仍可获相应成长，未完成不算一个完整失败周期。只统计实际生效后的记录。
- 历史提供按习惯日的明细和相应周期的目标/结果；未到结算日的累计目标显示「进行中」，不每天标红为失败。不加入家庭排名或额外连续打卡奖励。

#### 3.3 习惯日、保存和撤销

习惯域统一使用北京时间，**04:00 换日**。10 月 20 日的习惯日覆盖 10 月 20 日 04:00 至 10 月 21 日 04:00；10 月 21 日 00:20 的记录显示「记入 10 月 20 日」。

- 只能记录当前习惯日，不选择过去或未来日期。跨午夜不等于补记；04:00 之后不能新补旧日。
- 只有云端确认才显示保存成功。保留实际操作时间、本人身份、习惯归属日、目标版本和原请求回执。
- 每条记录从首次云端保存成功起有 **30 秒撤销**；撤销只取消该次记录，之后不可删改。刷新、重试、换日不重开窗口。
- 保存后立即反馈业务进度和可撤销的成长预览；撤销期结束后才成为可投入生产的成长。旧的成熟成果仍可照常收售。
- 03:59:50 保存成功，可撤销到 04:00:20；这是撤销已有记录，不允许在新一天补录旧日。
- 结果未知时用原请求确认/重试：曾成功就返回原日期和截止时间；从未成功且请求已跨日则保留输入并明确告知过期，不悄悄改记今天。要记新一天必须由本人重新提交。
- 重放先验证当前身份仍有读取资格，再按原请求 ID 和原载荷查询既有回执；已有成功结果不能因后来归档或目标变更被误报成失败。仅尚未执行的新请求检查当前日期、归档状态和目标版本。同一请求 ID 携带不同载荷直接拒绝。
- 多个窗口同时打卡、追加、撤销，均以云端结果为准；相同请求不能重复记量，打卡型不能重复完成同一应做日。

### 4. 修改、归档与恢复

名称、公开范围立即生效；目标、完成方式、单位和周期通过未来版本改变，旧记录永远按原版本解释。不同单位的历史分段展示，不把「页」与「分钟」拼成一个总量；同量纲时长可明确换算展示。

本规格采用**当前规则的结算周期**决定修改生效点：

| 当前规则 | 修改生效时间 |
| --- | --- |
| 按日安排，包括指定星期、每 N 天、月指定日 | 下一习惯日 04:00 |
| 每周 N 天、每周累计 | 下周一 04:00 |
| 每月累计 | 下月 1 日 04:00 |

生效前继续原规则。新规则若从某个周/月中途开始，该首段标为不完整周期，只计生效后的记录，不重新解释此前记录。设置页同时列「当前规则」与「某月某日生效的规则」；首版只保留一个待生效版本，可以修改或取消。未改的每 N 天安排保留原锚点；主动改为新的间隔安排时以生效日作为新锚点并展示日期预览。

同一记录只属于一个规则版本，一次达标只发一次成长；改目标、刷新、归档恢复都不能重复发奖。

- 不再继续时使用归档，无删除历史和单独暂停模式。
- 归档移出进行中清单和六位场景，停止新记录及自动续种，保留规则、历史、当前轮、成长和待收篮。以前已成熟成果仍能收取、出售。
- 归档前已保存记录保留原撤销截止时间；如果撤销期在归档后才结束，有效成长进入原习惯的未分配余额，归档期间既不推进旧轮，也不启动新轮。恢复后先继续保留的原轮，再处理下一轮，作物和动物遵守同一规则。
- 恢复后按当前习惯日和已生效规则继续，不补停做期间，不重置已完成日/周/月的记录与成长发放标识。包含归档中断的周期明确标记，未达标不冒充完整失败周期；实际完成与已得成长保留。
- 归档不丢库存、币或设施。动物占用释放及恢复生产按下一节处理；不因归档额外退种子或转换当前品种。

归档、恢复、换种、动物移动、规则变更等操作前，先按云端业务时间结算此前已经生效的记录和生产，再执行该操作。例如记录在 12:00:30 锁定、12:02 才归档，12:00:30 应得的成熟和续种结果不能因延迟到归档时读取而消失；反过来，12:00:20 已归档则按上面的冻结规则处理。不以哪个面板先加载决定结果。

### 5. 成长、生产与收取

#### 5.1 一习惯一份进度

每条习惯有独立成长、种养轮次和待收篮。**3 格成长完成一轮，每轮产出一份商品。** 部分达标只显示业务进度，未获得的成长不能提前出售；已确认成长跨日期和周期保留。

六个场景位置只是展示容量。按稳定创建顺序分组，超过六条可切组；未展示的习惯照常记录和成长。已归档习惯在归档列表查看，不占活跃展示位。

明确区分：

1. **未分配成长**：还没投入某轮，可留存并用于同一习惯下一次选择的品种，不能转给别的习惯。
2. **当前轮进度**：已经投入某作物或动物生产轮的 0–2 格，绑定该轮品种；不能换成另一产物或抽回当通用成长。
3. **成熟成果**：该轮结束后进入待收篮，保留原品种和数量。

例如缺货时存下 6 格，后来为该习惯选择南瓜并备好两包种子，可以完成两轮南瓜。每轮都要消耗种子，不重复使用格数；原先番茄轮已有的 2 格不能改成南瓜。

#### 5.2 种子与自动续种

- 第一次播种由本人选择并确认，开始一轮消耗一包对应种子。
- 成熟后有同品种库存就自动续种，不要求先领取前一轮；缺种子就等待，后续成长留存。
- 不自动花币补货，不擅自改成免费品种。免费种子也按本人选择的数量入库，不等于无限库存。
- 提供「本轮完成后换种」。明确选择优先于默认同品种续种；开始下一轮仍需对应种子或可分配动物，没有就等待，不静默回退。
- 已自动播种的新一轮也不能中途变种；界面明确显示本轮是什么、换种在哪一轮生效。等待播种时可以直接为下一轮选新品种。
- 归档停止续种；恢复后继续原轮或已选下一轮。购买种子只补充库存，不凭空增加成长。
- 通用商店补货成功后，等待续种的活跃习惯自动检查新增库存；同品种不足时按进入等待状态的时间先后分配，同时间按稳定创建顺序。待收和成长结算同样不取决于当前可见分组。
- 从某条习惯的「购买并播种/补种」入口明确购买时，先满足此次明确指定的种养位，剩余库存才供自动续种；确认页显示价格、数量和去向，库存版本冲突先刷新确认。第一次播种仍需本人明确选择。
- 「下轮换种优先」指该习惯优先采用本人选定的品种，不提前占用库存，也不抢走其他习惯已投入轮次的种子。通用补货确认页显示等待续种的分配次序，避免买入后去向不明。

#### 5.3 永久动物

动物每只单独购买，长期持有，完成一轮产生蛋或羊毛；动物不会在收取后消失，也不因漏打受惩罚。

- 每只动物同一时刻只分配给一条进行中的习惯；动物列表显示「可用」或当前占用习惯。
- 一个习惯同一时刻只有一种生产轮，不能同时养鸡和种南瓜来重复消费同一份成长。
- 归档或移回仓库可以释放动物，但原习惯的品种和已投入进度留在原处。没有同品种可用动物时不能继续结算该轮动物产物，重新分配后继续。
- 动物搬动不转移成长、不复制当前轮；改为另一品种仍须完成原轮，再执行下一轮选择。原待收蛋/羊毛保持原样。
- 不引入饲料开支、疾病、寿命、繁殖、动物转售或按现实时间自动生产。

#### 5.4 待收篮和仓库

成熟成果保留，不腐坏、不阻止下一轮。支持逐习惯收取及「收取全部」，后者覆盖本人全部成熟成果，包括未展示分组和归档习惯，不受当前六位限制。

收取只是把待收成果移到本人仓库；出售是另一个明确动作。一次领取不能重复发货，部分失败/未知结果可安全确认重试。仓库选产物及数量，先显示获得多少农场币，再出售；不会自动卖掉所有东西。

### 6. 首版商品与经济

初始 **0 农场币**，没有真实习惯、已种作物、动物或购买设施。始终可免费领取基础雏菊种子，避免花光币后无法继续；仍需有效成长才能成熟。

所有币均为游戏货币，与人民币、财务市区账本及财务等级无关。

| 品种 | 买价 | 一轮产物及售价 | 作物每轮净收益 / 动物单轮收入 |
| --- | ---: | --- | ---: |
| 雏菊 | 种子 0 | 花束 ×1，卖 10 | 10 |
| 向日葵 | 种子 10 | 花束 ×1，卖 25 | 15 |
| 番茄 | 种子 25 | 番茄篮 ×1，卖 50 | 25 |
| 南瓜 | 种子 60 | 南瓜 ×1，卖 100 | 40 |
| 鸡 | 每只 180 | 鸡蛋份 ×1，卖 30 | 30，未扣首次购入成本 |
| 羊 | 每只 420 | 羊毛份 ×1，卖 35 | 35，未扣首次购入成本 |

作物种子每轮消耗，动物无后续种子成本；两类均为三格一轮。鸡、羊分别要 6、12 轮收入覆盖初次购入价格，这不是相对于免费种植的净回本期。

| 永久外观设施 | 价格 | 固定位置的可见变化 |
| --- | ---: | --- |
| 入口花盆组合 | 30 | 门口多层花盆与花簇 |
| 长椅与花坛组合 | 80 | 座椅、铺装与分层花坛 |
| 花园围栏与门廊 | 180 | 装饰门廊、精细栅栏、攀缘植物 |
| 藤架凉亭 | 400 | 藤蔓、遮阴结构、座位和小径 |
| 温室扩展 | 600 | 新的温室附属空间和内部陈设 |
| 装饰风车升级 | 900 | 风车结构细节及可独立运动的叶片 |

每款设施限持有一份，购买成功后安装在预设位置、各习惯分组共用，永久保留。只增加外观，不提升生长、产量或售价。基础建筑、必要围栏和后来购买的新增几何明确区分，不把现有同一设施重复出售。具体坐标在既有农场边界内完成建模、通行与多视角验证。

只出售收获产物；不提供种子、动物、设施转卖、赠送、家庭共享钱包或玩家交易。首版价格固定明示；成交由云端目录判定。报价变化时先展示新价格，不能按未知新价直接成交；历史回执保留原价。

一条每日习惯按「雏菊→向日葵→番茄→番茄→持续南瓜」及时收售，第 3/6/9/12/15 天的余额为 10/25/50/75/115；持续不买其他物品时，第 21 天 195，第 39 天 435。三条每日习惯的一条再投资路线第 18 天为 495。它们是算例而非最快升级承诺，完整逐轮收支见 [价格草案与算例](../planning/habits-economy-draft.md)。

### 7. 页面与日常交互

以「我的农场」为主工作区，界面职责和代码模块一样分开。

| 入口/区域 | 内容与动作 |
| --- | --- |
| 我的农场 | 本人六个可见种养位、分组、成长与待收、进入习惯详情、新建习惯 |
| 习惯详情 | 当前目标/周期、今日或周期进度、追加/打卡、30 秒撤销、历史、未来规则、分享与归档 |
| 待收篮 | 逐习惯成果与收取全部，包含未展示组和归档成果 |
| 仓库 | 收获产物、种子、动物占用；选择数量出售或分配种养 |
| 商店与建设 | 单价、数量、余额、已持有状态、购买与补种去向；设施固定位置预览 |
| 家人记录 | 当前家庭公开习惯的只读列表与完整记录；不替换个人农场 |
| 归档列表 | 历史、遗留轮次和待收、恢复；无打卡入口 |
| 应用内今日 | 本人应做日清单，以及本周/月尚需完成的目标；点击进入对应习惯 |

- 第一次进入显示空农场引导：创建习惯 → 领取种子 → 明确播种。没种养也可记录和存成长。
- 习惯卡分别显示「阅读 20/30 分钟」和「番茄 2/3 格」，避免把业务目标与经济进度混成一个数字。
- 「成长中」「缺种子」「待收 2 份」可以并存。待收篮有产物时不覆盖正在进行的新一轮；可撤销预览与已确认进度有明确区别。
- 点击地块/标牌进入对应习惯；桌面面板可与场景并排并支持收起，移动端使用可滚动的单列面板。保存、撤销和返回始终可触达；手机不依赖悬停。
- 创建/编辑失败保留当前输入。保存中和结果未知有独立状态；不能关闭提示后把未知写入当成失败，或让重试重复扣币。
- 固定设施预览明确标「未购买」，不写余额或冒充已持有；选择种养时展示实际库存、所需种子/动物和将使用的成长。
- 应用内提醒是今日列表、目标剩余量和入口提示。**不请求系统通知权限，不发邮件，也不提供暗示后台提醒的时间设置。** 页面关闭期间不通知。

### 8. 真实模型、氛围与扩展

保留原农场城市位置、60×92 m 边界、六个展示地块及已批准的建筑品质；保持七街区 ID、道路和米制比例。原先硬编码的六品种与 72 个节点不再定义真实库存、成长奖励或展示数量。

- 使用 Blender 可复现生成的真实 GLB，拆分基础农场、种养组合和购买设施；不使用图片冒充场景。
- 同一种养组合可放到任一展示位。作物表现刚播种、成长 1/3、成长 2/3，以及成熟成果；自动续种后当前植物与待收篮分别展示。
- 动物本体长期保留，阶段变化表现蛋/羊毛等产物与互动，不每轮把成年动物变回幼体。成熟表现与仓库数量一致，但不要求每份商品都生成一个无上限网格对象。
- 改善床土、枝叶、围栏、标牌、温室内部、仓储和商店细节，维持现有暖色、舒适城市风格；商店循环参考官方牧场游戏资料，使用原创资产。
- 设施固定插槽避开主路、地块入口和行人路径；温室扩展/风车升级优先整合既有建筑，不堆到种养位或公共道路中。
- 复用街上行人与场景持有的活动生命周期。农场提供浇水、查看作物、喂养、采收和逛店地点；行为仅视觉，不代替真实打卡、收取或交易。
- 延续昼夜照明、暂停和减少动态效果设置。切组、换账号、归档、换种时清理相关模型、灯光、动画和小人占用；迟到加载不能恢复旧状态。
- 只加载当前需要的种养组合，重复几何可复用；大量习惯和待收库存不使场景对象数量无限增长。兼容移动端与原有财务模型加载/释放机制。

## User Stories

以下故事只展开已确认范围，US 编号供开发票及验收追溯；不因故事拆细新增功能。

1. **US01 · 统一登录与入口权限**：作为家庭成员，我希望从地图、目录、今日清单或推荐进入习惯功能时经过同一个登录与权限入口，以便登录后继续原本想做的事，并清楚区分未登录和无访问资格。
2. **US02 · 本人操作与家庭身份隔离**：作为习惯拥有者，我希望只有当前家庭中有账号的本人能创建、修改、记录、撤销和归档我的习惯，以便个人记录不会被其他家人代写或跨家庭访问。
3. **US03 · 默认私密且管理员无例外**：作为新建习惯的成员，我希望每条习惯默认仅自己可见，以便在主动分享之前，包括管理员在内的其他人都看不到我的目标和记录。
4. **US04 · 完整记录的家人只读分享**：作为愿意分享的成员，我希望逐条将习惯设为全家可见，以便当前同家庭成员能在独立入口查看该习惯的名称、目标、规则历史、完整记录和数量或时长。
5. **US05 · 收回公开访问**：作为曾公开习惯的成员，我希望随时改回仅自己可见，以便后续云端读取立即拒绝其他家人访问，已打开的分享视图也在权限刷新时清空。
6. **US06 · 切换身份时清除个人状态**：作为会退出或切换账号的成员，我希望前一身份的个人界面、场景和待提交操作立即清除，以便下一位使用者不会看到我的习惯或经营资产。
7. **US07 · 全部入口使用本人投影**：作为农场主人，我希望地图、今日清单、顶栏习惯计数、地图徽标和首页习惯推荐都只反映本人的习惯，以便私密活动不会通过汇总或共享成长透露给别人。
8. **US08 · 真实空状态起步**：作为首次使用农场的成员，我希望从 0 农场币、空习惯、空种养、无动物和无购买设施开始，以便所有进展都来自本人真实操作。
9. **US09 · 自定义个人习惯**：作为准备培养习惯的成员，我希望填写名称并选择完成方式、目标、周期和公开范围，以便建立符合自己生活安排的习惯。
10. **US10 · 手动完成打卡型习惯**：作为使用打卡型习惯的成员，我希望亲自确认是否完成目标，以便系统准确记录我的判断而不会根据点击时刻猜测行为是否发生。
11. **US11 · 追加数量与手动时长**：作为使用计量型习惯的成员，我希望追加本次完成的正数数量或时长，并在保存前看到本次量、归属日和合计，以便不会把追加误当作覆盖当天总量。
12. **US12 · 达标后保留真实超额记录**：作为实际完成量可能超过目标的成员，我希望达标后仍能追加真实数量或其他日的完成，以便历史完整而成长奖励不会因超额或重复操作膨胀。
13. **US13 · 未播种也可先积累**：作为刚创建习惯的成员，我希望可以先记录习惯、保留有效成长，再按引导领取种子并明确播种，以便选品种不会成为记录行为的前置障碍。
14. **US14 · 每天或指定星期执行**：作为有固定日程的成员，我希望设置每天或指定星期执行，以便只在应做日记录并按当日目标获得成长。
15. **US15 · 每 N 天执行**：作为有间隔计划的成员，我希望每 N 天的安排从开始日锚定并预览接下来三个应做日，以便漏做或归档恢复不会悄悄改变节奏。
16. **US16 · 每月日期与月末执行**：作为按月安排习惯的成员，我希望选择每月指定日期或明确的月末，以便短月份不会把不存在的日期擅自挪到别的日子。
17. **US17 · 每周任选 N 个达标日**：作为需要灵活安排运动的成员，我希望一周内任选 N 个不同习惯日分别达到当日目标，以便一天集中做很多不会替代多天的坚持。
18. **US18 · 每周或每月累计目标**：作为关注周期总量的成员，我希望将当前周或月内各习惯日的数量相加判断目标，以便“每周累计 90 分钟”与“每周三天各 30 分钟”有清楚区别。
19. **US19 · 首个不完整周期**：作为在周/月中途开始或切换规则的成员，我希望首个不完整周期被明确标记，并只统计生效后的记录，以便历史不会被回填或误当作完整失败。
20. **US20 · 可解释的习惯历史**：作为回顾习惯的成员，我希望按习惯日查看明细、实际操作时间、目标版本与周期结果，以便知道每次记录如何被统计。
21. **US21 · 北京时间 04:00 的习惯日**：作为在午夜后活动的成员，我希望习惯域统一在北京时间 04:00 换日，并明确显示记录归属，以便午夜后记录仍准确属于刚过去的晚间。
22. **US22 · 当前日记录与历史锁定**：作为遵守记录规则的成员，我希望只有当前习惯日能够新增记录，以便没有补历史、填未来或覆盖旧总量的隐含入口。
23. **US23 · 云端确认与失败保留输入**：作为在线保存的成员，我希望只有收到云端确认才看到保存成功，失败或离线时保留输入，以便能够重试而不丢失本次准备记录的内容。
24. **US24 · 固定 30 秒的单条撤销**：作为可能误触的成员，我希望每条记录自首次云端保存成功起有 30 秒撤销，以便及时取消该次操作而不修改其他记录。
25. **US25 · 可撤销预览与正式成长分开**：作为农场主人，我希望保存后立即看到业务进度与成长预览，但只有过撤销期的有效成长能投入生产，以便撤销不会造成已出售的虚假资产。
26. **US26 · 跨日未知请求安全重试**：作为遇到网络丢响应的成员，我希望使用原请求确认或重试，以便已成功记录不重复、未成功的过期输入也不会被默默记到新一天。
27. **US27 · 归档或规则变化后的回执重放**：作为在多个窗口操作的成员，我希望后来归档或修改规则不把此前已成功但响应丢失的请求误报为失败，以便能够确认真实结果并安全继续。
28. **US28 · 修改设置但保留历史含义**：作为习惯拥有者，我希望名称和公开范围立即更新，目标、完成方式、单位和周期只通过未来版本改变，以便调整计划而不篡改过去。
29. **US29 · 明确的未来生效日期**：作为调整计划的成员，我希望同时看到当前规则和唯一一份待生效规则及其生效时间，以便知道下一次记录遵循什么目标。

33. **US33 · 恢复原习惯继续执行**：作为重新开始习惯的成员，我希望恢复后按当前习惯日和已生效规则继续，以便保留积累且不追补停做期间或重领奖励。

52. **US52 · 一次购买永久外观设施**：作为想美化农场的成员，我希望购买设施后在预设位置看到永久的真实建设，以便经营收入转化为可见的环境改善。
53. **US53 · 设施预览与固定安装**：作为考虑购买设施的成员，我希望先看到明确标为未购买的固定位置预览，以便了解效果而不误以为已拥有或提前扣款。
54. **US54 · 清楚的工作区与进度表达**：作为日常使用者，我希望从我的农场进入习惯详情、待收篮、仓库、商店、家人记录或归档列表，并分别看到业务目标与种养进度，以便每个操作都有明确去向。
55. **US55 · 六位稳定分组**：作为拥有七条以上习惯的成员，我希望按稳定创建顺序切换每组六个展示位，以便所有习惯都有可识别位置且未展示的进度照常运行。
56. **US56 · 桌面和手机都能完成闭环**：作为在不同屏幕上使用的成员，我希望桌面可并排或收起面板、手机可单列滚动操作，以便保存、撤销、返回和全部经营动作始终可达。
57. **US57 · 仅应用内的待办提示**：作为不需要外部提醒的成员，我希望应用内今日清单、剩余目标和入口提示帮助我回到待办，以便在打开应用时知道接下来做什么。
58. **US58 · 保留城市布局的真实农场**：作为喜欢现有小城的成员，我希望新农场使用真实可交互 GLB 并保留城市位置、边界、六地块和建筑品质，以便成长发生在可信的三维环境中。
59. **US59 · 可辨认的作物与动物阶段**：作为观察成长的成员，我希望从多个角度辨认播种、1/3、2/3 和成熟成果，以及动物产物的变化，以便场景与真实经营状态对应。
60. **US60 · 复用街上行人的农场活动**：作为浏览小城的成员，我希望现有街上行人能进入农场浇水、查看、喂养、采收和逛店，以便农场显得有人使用且动作符合实际路径。
61. **US61 · 昼夜、减少动态效果与资源清理**：作为长时间浏览或偏好少动画的成员，我希望农场响应昼夜、暂停和减少动态效果设置，并在切组或切换身份时清理旧资源，以便体验稳定且视觉控制不影响业务结果。
62. **US62 · 普通新品种容易扩展**：作为维护农场内容的人，我希望通过稳定目录定义、真实资产和相应验证增加同类品种，以便持续丰富内容而不重写打卡、生产、收取或交易流程。
63. **US63 · 并发交易与资产守恒**：作为可能在多个窗口操作的成员，我希望记量、撤销、发格、耗种、收取和买卖都在同一授权云端业务边界保证一致，以便失败重试不会丢输入、重复记量或制造资产。
64. **US64 · 每个分片有真实验收**：作为验收使用者，我希望第一条可用业务链就接通真实云端，并在每个分片验证相应流程，以便没有到最后才发现权限、保存或模型只是本机演示。
65. **US65 · 全城回归与可复现交付**：作为项目维护者，我希望上线交付同时保留生成命令、迁移、部署配置、资源预算和回归证据，以便能够复现农场并确认既有城市功能持续可用。

## Implementation Decisions

### 9. 模块与云端边界

延续 Vercel + Supabase 路线、现有身份与家庭体系；新习惯业务使用独立数据边界和版本化迁移。真实账户从空状态开始，不迁移 localStorage demo 成长、任务、库存或币。

| 边界 | 职责 |
| --- | --- |
| 习惯与周期 | 本人归属、可见性、目标版本、归属日、追加/撤销、归档、达标依据 |
| 成长与生产 | 一次达标一次发格、未分配成长、种养轮次、种子消耗、动物占用、成熟成果 |
| 商品目录与交易 | 稳定品种/物品标识、报价、库存、钱包、购买/出售/收取及回执 |
| 授权后的页面状态 | 本人今日和农场、家人只读记录、身份切换、失败输入与未知结果 |
| 场景与资产目录 | GLB、阶段、灯光、交互锚点、行人活动、加载释放与分组显示 |

通过清晰接口与构造注入组合，使用少量作物/动物生产策略，不按品种名堆业务分支。新增同类品种应主要增加目录定义、真实资产和验证，不重写打卡、生产、收取或交易；真正新增机制时才扩展策略。首版不造商品管理后台或任意脚本引擎。

目录有稳定 ID 和版本。下架/改价不抹掉已有物品、动物、设施、成熟成果或成交记录；旧产物保持原定义。资产契约包含米制尺寸、地块占地/高度、局部原点、阶段节点和活动锚点，添加品种不要求重导出整城。

所有记量、发格、耗种、成熟、收取、买卖在授权后的云端业务边界判定。数值使用有明确精度的存储与运算，不信任客户端价格、日期、余额或成长数。事务确保库存/余额不为负、产物与投入守恒；请求去重与版本冲突处理覆盖刷新和多个窗口。生产结算可按请求补齐，但结果只取决于有效记录和库存事件，不能取决于是否打开当前分组。

第一条可用业务链就验证浏览器到云端；不能先做本机商店再延迟真实授权和并发。沿用在线保存，离线保留未提交输入并提示，不自动合并未知状态。

## Testing Decisions

### 10. 用户场景与验收

每个开发分片都附本地检查、同一云端业务边界验证和适用的应用内浏览器证据；所有写验收使用隔离测试家庭，不向真实家庭植入演示数据。

| 编号 | 必须通过的场景 |
| --- | --- |
| HF01 | 新账号 0 币、空习惯与空种养，旧 demo 不导入；创建阅读习惯、领取免费种子、播种、云端刷新仍一致 |
| HF02 | 本人可读写私密习惯；同家庭另一成员及管理员都不能读取；公开后可看完整记录但不可写，改回私密后后续读取被拒绝 |
| HF03 | 打卡去重；10+15 分钟合计 25；无历史/未来写入与覆盖总量后门；超额不多发成长 |
| HF04 | 每日、指定星期、每 N 天、月指定日/月末、每周 N 天、周/月累计分别按规则判断；不存在日期、首个不完整周期与不同量纲历史可解释 |
| HF05 | 跨午夜、周/月交界的 04:00 归属正确；03:59:50 保存可撤销至 04:00:20；重复/迟到请求不改归属或延长窗口 |
| HF06 | 30 秒内撤销重算预览；窗口结束不能删改；尚可撤销的成长不能生成可领取/出售资产，既有成熟成果不受阻 |
| HF07 | 目标/周期未来生效，不重算过去；多次编辑只形成一个待生效版本；归档恢复不补打、不重发已获成长 |
| HF08 | 三格一轮；日目标与周/月累计发格正确；部分/超额、重复收取及并发调用不重复发格或产物 |
| HF09 | 已有同品种库存自动续种；无货不花币、不换免费品种；存 6 格加两包南瓜恰好得两轮，已投入番茄轮与旧成果不变种；两习惯等一包种子时按固定顺序分配，定向补种去向明确 |
| HF10 | 手动下轮换种优先于默认续种；动物同一时刻不被两习惯占用；移动/归档/恢复不转移成长、不复制动物产出 |
| HF11 | 未收不腐坏且继续生产；收取全部涵盖未展示和归档成果；收取只入库，出售才加币；同产物并发出售至多使用现有数量 |
| HF12 | 六品种与六设施价格/收益、免费种子数量正确；余额不足保留选择；重复购买永久设施不重复扣币；报价变化先重新确认 |
| HF13 | 七条以上习惯切组不影响隐藏组生产；设施各组一致；家人公开记录不贡献本人成长或住宅；退出/换身份不泄露上一账号的界面或模型 |
| HF14 | 真实 GLB 每种阶段、动物产物、固定设施可从多个视角辨认；实际尺寸、通路、行人入口与防穿模检查通过 |
| HF15 | 自动续种的当前轮与旧待收成果在视觉上可区分；小人互动、昼夜/暂停/减少动态效果不触发业务交易；切换释放资源 |
| HF16 | 桌面与窄屏应用内浏览器完成创建→记录→收取→出售→购买→换种→归档/恢复并刷新验证；登录/权限弹窗仍为应用级 |
| HF17 | 断网、失败、丢响应、重复提交、两窗口并发、权限变化均通过同一云端接口验证；不丢输入、不重复扣款、不出现负库存/余额 |
| HF18 | 加一个同类测试品种，只改目录/资产/校验即可走通通用流程；真实财务、图鉴、住宅健康、交通和部署回归通过 |

为便于复现，时间边界、30 秒与并发用可控时钟/公开业务接口测准确性；最终真实账户和真实 GLB 仍在应用内浏览器验收，不用测试注入替代端到端证据。生成命令、迁移、部署配置、回归结果和资源预算需随交付留档。

### 测试入口及既有先例

用户已在完整方案确认中接受这些入口，无需再访谈：以应用内浏览器到正式云端业务接口为最高验收边界；授权、并发、丢响应和重放从同一业务接口检查，复用既有财务跨账号、原请求回执与真实响应丢失测试的方式。精确日期/数量/成长守恒用可控时间的业务规则测试，实际模型和行人路径用 Blender 导入真实 GLB 的尺寸/身体通行检查补充，避免为每个内部函数单独造测试入口。

好的测试验证用户可观察结果与数据守恒，不锁定私有函数调用、表内布局或类名。每片新增的习惯、生产、交易、授权投影与场景契约随该片验证，不能统一拖到最终集成。复用现有纯状态测试、真实云端竞态测试与场景资源/活动生命周期测试的组织方式。

首个每日打卡分片在线验证当前日保存、30 秒撤销、真实模型 0→1 格及刷新；三日成熟路径用受控时间的同一业务边界测试并明确标注来源，不要求等待三个自然日，也不把预置历史宣称为真实连续打卡。周累计分片能在当天通过真实达标获得三格，必须补齐浏览器记录→成熟→收取的完整自然流程。受控时间不能暴露为生产客户端可调用的改时钟或补历史后门。

## Out of Scope

### 12. 本期边界

本期不做共享成长、代记/代管、无账号习惯成员、历史补打/任意删改、系统推送/邮件、后台计时或设备同步、自由摆放、设施经济加成、季节/饲料/疾病/繁殖、加工链、玩家交易、真实货币购买、排行榜或财务联动。其他街区继续保留既有范围，不能把新的个人成长悄悄接入公共成果。

## Further Notes

### 11. 已确认的交付方向

以下是用户确认的交付方向；具体任务粒度和直接依赖在拆票索引中列出。每片独立验收，不把云端验证留到最后。

1. **首条真实闭环**：本人习惯、每日打卡、空状态、三格成长、免费基础作物与收取；从首片接入云端、认证、撤销及一块真实场景投影。
2. **完整记录规则**：计量、全部周期、04:00、未来目标版本、历史、归档恢复与家人只读；补齐相应权限和时间边界验收。
3. **经营闭环**：仓库、出售、钱包、种子购买、自动续种、储存成长与换种；逐片验证真实交易和安全重试。
4. **长期资产与扩展**：动物占用、设施购买、稳定商品目录/生产策略、可扩展模型契约。
5. **完整农场表现**：六品种全阶段、六设施、六位分组、待收表现、昼夜与街上行人活动、移动端交互；与对应业务片并行制作资产。
6. **整体验收与上线交付**：完整应用内流程、云端权限/并发回归、模型/资源验证、财务及全城回归、操作文档。
