# 街区提供活动，城市行人负责执行

2026-09-22，用户要求道路行人与街区建筑发生互动，从财务市区开始，并采用面向对象与 IoC，方便以后扩展其他街区。

采用场景作用域的对象组合和显式依赖注入。`CityScene` 创建一个 `PedestrianActivities`，分别注入行人模拟与财务街景。`DistrictActivities` 提供街区入口、可走路线和可预约的活动地点；内部 `Visit` 管理进入、行走、停留、室内访问、购物与离开的生命周期。街区不直接控制 Three.js 行人对象，活动模块不读取财务账、DOM、系统时间或数据库。

设施停留点一次只分配给一个访客。访客使用现有道路行人身份与关节模型，进店时在门口隐藏、停留后从同一个入口出现，购物后携带三维手提袋。普通访问沿路线回到出发的人行道；等级切换或卸载时取消预约，将访客恢复到其街道位置，避免继续穿过新的建筑。暂停、页面隐藏与减少动态效果共用场景的视觉时间控制；昼夜预览不推进暂停的活动。

路线是与真实建筑配套的米制通行图，而不是运行时直线寻路或完整导航网格。财务 Lv.1 和 Lv.2 使用不同配置，Blender 重新导入实际 GLB 后检查沿途身体通行空间。新街区可以注册同一个 `DistrictActivities` 的不同配置；活动类型只是地点描述，不需要增加中央分支。特殊行为未来可以实现相同提供方接口，再注入场景，不预先增加容器、继承层次或插件加载器。

本次只接入已交付的财务 Lv.1–2。后续财务等级应与各自建筑一起交付活动图；其他板块在各自功能开发时接入。动画里的购物、银行活动只表达城市氛围，不写账、不改变金额、不触发成就。
